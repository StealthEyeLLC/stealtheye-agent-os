# Compliance

This document maps design intent to readiness frameworks. It does not claim certification, legal compliance, or audit completion.

| Area | Intent |
|---|---|
| NIST AI RMF | Govern, map, measure, and manage AI risks through authority envelopes, evals, receipts, and risk register. |
| EU AI Act | Preserve documentation, risk classification, human oversight, evidence, and data governance readiness. |
| ISO/IEC 42001 | Establish AI management-system evidence: policies, roles, risk, monitoring, and improvement loops. |
| NIST CSF 2.0 | Identify, protect, detect, respond, and recover controls for agent infrastructure. |
| NIST SSDF SP 800-218 | Secure design, dependency hygiene, CI checks, provenance, and vulnerability response. |
| OWASP LLM Top 10 / Agentic AI threats | Prompt injection, data leakage, excessive agency, tool misuse, supply-chain/tool poisoning, and insecure plugins. |
| SOC 2 readiness | Security, availability, confidentiality, processing integrity, and privacy evidence. |
| ISO 27001/27002/27701 readiness | ISMS/PIMS control mapping, risk treatment, access control, incident response, and privacy operations. |
| GDPR/CCPA readiness | Data minimization, purpose limitation, access/deletion workflows, and processor evidence. |
| SLSA/SBOM/provenance | Build provenance, SBOMs, dependency scanning, signed releases/manifests. |
| Sector-triggered frameworks | PCI, HIPAA, FedRAMP/CMMC, and WCAG apply only when product scope triggers them. |
