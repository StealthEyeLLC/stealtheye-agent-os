# Secure SDLC

## Required practices

- Threat model high-risk components.
- Use branch-based PR review.
- Keep CI truthful about what is and is not tested.
- Add evals for security regressions.
- Use dependency scanning and SBOM generation.
- Review signed manifests and schema changes.
- Never weaken tests/security controls to pass.

## NIST SSDF alignment

Plan secure requirements, protect the software, produce well-secured software, and respond to vulnerabilities through documented fixes, receipts, and regression evals.
